# سیماب — بسته اصلاح عملکرد و امکانات، مرحله ۱

**وضعیت: آماده بررسی و استقرار مرحله‌ای؛ هنوز روی main نیست.**

این بسته این تغییرات را دارد:
- مأموریت جدید از پنل مدیریت به Supabase منتقل می‌شود و برای همه کاربران قابل مشاهده است.
- حذف مأموریت، آن را برای همه غیرفعال می‌کند؛ حذف ردیف‌های قبلی کاربران یا دستکاری سکه انجام نمی‌شود.
- قبل از عملیات مدیریتی، سرور امضای Telegram initData و شناسه مدیرِ ثبت‌شده در دیتابیس را بررسی می‌کند.
- ارسال پیام از کانال دیگر «باز کردن Share» نیست؛ سرور می‌تواند با دکمه مدیریت از طرف ربات پست بگذارد، *اگر* ربات در کانال مدیر باشد.
- هیچ تایمر یا لینک ساده‌ای دیگر مجوز ایجاد سکه جدید نیست. سیستم اعتبارسنجی مأموریت و پرداخت اتمیک هنوز جداگانه باید ساخته شود.

## کارهایی که صاحب پروژه باید به ترتیب انجام دهد

۱. SQL را از `supabase/migrations/20261012_central_quests_admins.sql` در پروژه **simab-game** اجرا کند.
این SQL فقط دو جدول جدید می‌سازد و به موجودی قبلی دست نمی‌زند.

۲. در Supabase > Edge Functions > Secrets نام `SIMAB_TELEGRAM_BOT_TOKEN` باید از قبل وجود داشته باشد. توکن را هرگز در کد، چت یا GitHub قرار نده. برای کانالی که واقعاً تحت مدیریت توست، Secret دیگر با نام `SIMAB_TELEGRAM_CHANNEL` تعریف کن. مقدارش نام کانال عمومی واقعی شبیه `@ExampleChannel` یا شناسه عددی `-100...` باشد. ربات باید در آن کانال اجازه ارسال پیام داشته باشد.

۳. در Supabase > Edge Functions، تابع جدید به اسم **simab-central-quests** بساز. کد *کامل* `supabase/functions/simab-central-quests/index.ts` را داخل `index.ts` قرار بده. گزینه `Verify JWT with legacy secret` را برای همین تابع **خاموش** کن، چون اعتبارسنجی امضای تلگرام داخل کد انجام می‌شود. به تابع‌های دیگر دست نزن.

۴. قبل از انتشار UI: از بخش Test با روش POST و JSON `{"initData":"invalid","action":"create"}` تست کن. باید **HTTP 401** و `{"error":"telegram_auth_failed"}` برگردد. سپس روش GET را تست کن؛ انتظار `{"quests":[],"rewardsEnabled":false}` است. اگر 503 برگشت، SQL، Secretها یا وضعیت سرویس را بررسی کن.

۵. بعد از موفقیت این تست‌ها، PR رابط کاربری را ادغام کن و پنل مدیریت را داخل **همان ربات فعلی** باز کن. یک مأموریت تست بساز و از گوشی دوم یا حساب مهمان بررسی کن که مأموریت دیده می‌شود. دقت کن پاداش هنوز فعال نیست.

## نکات مهم
- نام ربات و URL آن **نباید** عوض شوند؛ روی همان SIMAB باقی می‌مانند.
- ممکن است فایل‌های SQL دیگرِ فاز ۲ در شاخه‌های قبلی موجود باشند؛ این SQL مستقل از آنهاست.
- مقدار شناسه مدیر در جدول `simab_admins` از شناسه مدیر موجود در کد V6 گرفته شده؛ **این فقط شناسه است و جای تأیید HMAC را نمی‌گیرد**.
- نسخه فعلی کیف پول هنوز محلی/Telegram CloudStorage است؛ این بسته ادعای اتصال کیف پول به Supabase را ندارد.
- توکن ربات، کلید service-role و رشته کامل initData را در هیچ پیام یا اسکرین‌شاتی نفرست.

## بعد از این مرحله
مسیرهای باقی‌مانده: (۱) حساب واقعی تلگرام و مدیریت نشست، (۲) کیف پول سروری + دفتر تراکنش + مهاجرت کنترل‌شده سکه‌های قبلی، (۳) تأیید واقعی عضویت کانال و پرداخت یک‌باره مأموریت، (۴) تنظیمات بازی‌ها به‌صورت مرکزی، (۵) بهبود دستیار صوتی و پیام‌های رویدادها.
