# SIMAB — بسته یکپارچه کیف پول سروری، بازی امن و اصلاح کانال

## نتیجه بررسی
- کانال معرفی‌شده `https://t.me/SimorApp` است.
- در تصویر مدیران کانال، ربات `SimorMiniApp_bot` دیده می‌شود؛ اما برنامه قدیمی و تأیید HMAC/Ed25519 در Supabase برای **`@SimorApp_bot`** تنظیم شده است. این دو نام یکسان نیستند. **بدون دانستن هویت واقعی توکن Supabase نباید جایگزینشان کرد.**
- تصویر خطا هنوز نام Secret قدیمی `SIMAB_TELEGRAM_CHANNEL` را نشان می‌دهد؛ در شاخه فعلی کد رسمی کانال مشخص است و این Secret دیگر لازم نیست. بنابراین Edge Function قدیمی احتمالاً هنوز روی Supabase فعال است.
- SQL پاداش مأموریت قبلاً توسط کاربر اجرا شده است؛ آن را **دوباره اجرا نکن**.

## این بسته چه چیزهایی اضافه می‌کند؟
| جزء | سروری/تراکنشی | توضیح |
|---|---|---|
| کیف پول سکه و ژتون | بله | `simab_secure_wallets`، با RLS و فقط Edge Function احرازشده |
| دفتر وقایع | بله | `simab_secure_wallet_events`، شناسه منحصربه‌فرد و گزارش تاریخچه |
| عضوگیری کانال | بله | فقط تأیید واقعی عضویت توسط ربات مدیر + اعتبار یک‌باره |
| پاداش ورود روزانه | بله | یک بار در روز UTC؛ زنجیره تا ۷ روز با ساعت سرور |
| گردونه رایگان | بله | روزانه یک بار، نتیجه تصادفی از سرور و جایزه ثبت‌شده |
| ماینر پایه | بله | روشن‌کردن و برداشت هر ۸ ساعت با ساعت سرور |
| صرافی امن | بله | نرخ آزمایشی ۱:۱؛ انتقال اتمیک سکه ↔ ژتون |
| رولر امن | بله | ۳ ریل تصادفی سروری، پرداخت/کسر اتمیک و درخواست idempotent |
| پوکر و تخته‌نرد قدیمی | **خیر** | قوانین و محاسبات فعلی هنوز سمت کلاینت است؛ موجودی آن‌ها DEMO و **به کیف پول معتبر وصل نیست** |
| ماینر/گردونه/پاداش روزانه قدیمی | **خیر** | نسخه‌های قبلی هنوز آزمایشی‌اند؛ مسیر امن در صفحه جدید است |
| موجودی قدیمی مرورگر | **عمداً نه** | قابل اثبات نیست؛ خودکار منتقل نمی‌شود |
| حساب کانال | تأیید بعد از استقرار | مدیر بودن ربات در همان کانال باید با Bot API تأیید شود |

### نسخه جدید رابط
مسیر صفحه: `https://alihosseini6687-netizen.github.io/simor-app/wallet/`
در خانه، پوکر، تخته‌نرد، اسلات، گردونه، پاداش روزانه، صرافی و مأموریت‌ها لینک این کیف پول قرار گرفته است.

## مراحل فعال‌سازی با حداقل دخالت و بدون حذف موجودی فعلی

۱. **SQL (یک‌بار)**: در Supabase > `simab-game` > SQL Editor > New query فایل زیر را به طور کامل اجرا کن:
`supabase/migrations/20261013_secure_wallet_games.sql`
باید پیام `Success. No rows returned` دریافت شود. SQL موجودی قدیمی را پاک نمی‌کند و به هیچ مبلغ محلی اعتماد نمی‌کند.

۲. **ربات کانال**: کانال `@SimorApp` > Administrators > Add Administrator > **دقیقاً `@SimorApp_bot`** را به‌عنوان مدیر اضافه کن؛ **`SimorMiniApp_bot` ربات دیگری است**. برای ارسال پیام ربات، Post Messages را فعال کن. توکن را در چت یا اسکرین‌شات نفرست.

۳. **فقط بعد از موفقیت SQL و مجوز کانال**: در مخزن GitHub > Actions > **Deploy SIMAB central quests to Supabase** > Run workflow > `main` را انتخاب کن. این ابزار همان تابع مرکزی را با نسخه جدید منتشر می‌کند؛ GitHub Pages به تنهایی تابع Supabase را به‌روزرسانی نمی‌کند.

۴. **تست واقعی در تلگرام**: 
   - پنل مدیریت → «بررسی اتصال و حساب مدیریت»: هویت ربات، امضای مدیر و مدیر بودن ربات در کانال باید تأیید شود.
   - صفحه کیف پول → بروزرسانی؛ ابتدا ۰ سکه و ژتون یا موجودی قبلاً تأییدشده می‌بینی، نه سکه‌های محلی.
   - پاداش روزانه: یک‌بار جایزه، بار دوم بدون پرداخت.
   - گردونه: یک‌بار در روز UTC؛ بار دوم بدون پرداخت.
   - ماینر: روشن شود؛ برداشت قبل ۸ ساعت ممنوع؛ پس از زمان سروری امکان برداشت.
   - صرافی: با موجودی سروری سکه به ژتون؛ ژتون به سکه؛ موجودی منفی ممنوع.
   - رولر امن: شرط با ژتون سروری، نتیجه تصادفی روی سرور. تکرار یک requestId نباید دوباره شرط کم کند.
   - مأموریت عضویت کانال: عضو ۱ بار جایزه؛ غیرعضو نباید دریافت کند.
   - کیف پول قدیمی پوکر/تخته‌نرد/اسلات: این موجودی هنوز محلی و آزمایشی است و نباید مبلغ سروری را تغییر دهد.

## امنیت و محدودیت مهم
- تراکنش‌های امن فقط پس از تأیید امضای Telegram initData به شناسه واقعی کاربر روی سرور نسبت داده می‌شوند.
- از `initDataUnsafe` یا `localStorage` برای هویت یا مبلغ استفاده نمی‌شود.
- `SECURITY DEFINER` تنها برای `service_role` قابل اجرا است؛ `anon` و `authenticated` هیچ مجوز مستقیم روی جداول/توابع ندارند.
- نتیجه تصادفی فقط از `gen_random_uuid()` سمت PostgreSQL تولید می‌شود.
- `requestId` تکراری از دفتر تراکنش خوانده می‌شود و برداشت/جایزه تکراری نمی‌سازد.
- پوکر و تخته‌نرد چندنفره و موتور کامل تسویه سمت سرور، مهاجرت اعتبار محلی، و سامانه ضدربات/ریت‌لیمیت پیشرفته **هنوز انجام نشده‌اند**. پس این بسته یک نسخه بتای امنِ محدود، نه انتشار اقتصادی نهایی است.
- قبل از استقرار SQL، صفحه کیف پول به‌جای سکه‌سازی محلی، خطای آماده‌نبودن سرور می‌دهد.
- تست GitHub Actions با PostgreSQL 16 و Node برای SQL/JS اجرا می‌شود؛ باز هم تست داخل تلگرام بعد از Deploy لازم است.
