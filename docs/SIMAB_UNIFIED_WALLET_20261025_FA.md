# سیماب: کیف پول مشترک و میزهای سروری

واریز مدیریت قبلاً وارد کیف پول سروری می‌شد، ولی خانه و صرافی از موجودی قابل‌ویرایش دستگاه می‌خواندند. اکنون تمام صفحه‌های فعال از یک کلاینت مشترک، همان کیف پول سروری و یک شناسهٔ تلگرام امضاشده استفاده می‌کنند. موجودی ذخیره‌شدهٔ مرورگر یا Telegram CloudStorage وارد اعتبار معتبر نمی‌شود و مقدارهای بزرگ کاربران عادی دیگر به ۵۰ بازنشانی نمی‌شوند. دارایی محلی قبلی پاک یا خودکار منتقل نمی‌شود.

## رفتار مالی

- خرید ژتون: هر سکه یک ژتون، در یک تراکنش؛ حداکثر هر تبدیل ۱٬۰۰۰٬۰۰۰. برگشت ژتون به سکه هم اتمیک است.
- پوکر: ورودی ۲۰ تا ۱۰٬۰۰۰ ژتون در شروع از موجودی آزاد کم می‌شود و به موجودی روی میز می‌رود. شرط‌ها از موجودی میز مصرف می‌شوند. پایان دست، فقط ژتون باقی‌مانده و سهم واقعی پات به کیف پول برمی‌گردند. خروج از دست یعنی فولد و بازگشت ژتون شرط‌بندی‌نشده. بستن برنامه باعث پرداخت یا گرفتن ورودی مجدد نمی‌شود؛ دست فعال روی سرور قابل ادامه است.
- پوکر تگزاس بدون محدودیت افزایش، با ربات، میزهای ۲، ۴ و ۶ نفره؛ بلایند ۱ / ۲. کارت‌های پنهان و دستهٔ کارت روی سرور می‌مانند. ارزیابی دست، آل‌این، افزایش کامل/ناقص، پات جانبی و تقسیم مساوی روی سرور اجرا می‌شوند. این نسخه شبکهٔ چندنفرهٔ انسانی ندارد.
- تخته‌نرد: ورودی ۱ تا ۱۰٬۰۰۰؛ جایزهٔ برد ۲ برابر ورودی. تاس، بازگشت از بار، اولویت استفاده از حداکثر تاس و تاس بزرگ‌تر، ضربه، بیرون‌بردن مهره و برنده روی سرور بررسی می‌شوند. خروج وسط دست ورودی را مصرف می‌کند. دابل و ضریب مارس در این میز فعال نیستند.
- رول: همان ۹ نماد تصویری؛ سه صندوق ۵۰ برابر، الماس ۳۰، هفت ۲۰، سکه ۱۰، ژتون ۵؛ انرژی ۲۰ ضربدر ضریب انتخابی؛ دو نماد مثبت یکسان ۲ برابر. سه بمب/شلوار/جمجمه بدون جایزه‌اند و هیچ جریمهٔ اضافی خارج از شرط ندارند. نمونه‌گیری تصادفی رمزنگاری‌شده و بدون سوگیری تقسیم باقیمانده است. فاصلهٔ چرخش حداقل ۲ ثانیه.
- جایزهٔ روزانه و گردونه‌های دو مسیر قدیمی یک منبع مشترک روزانه UTC دارند؛ یک بار در روز. تغییر ساعت، جابه‌جایی صفحه و کلیک دوباره جایزهٔ اضافه نمی‌سازند.
- ماینر پایهٔ رایگان قبلی در کیف پول باقی است. دستگاه‌های قابل خرید، مخزن و زمان سروری مستقل دارند؛ هزینهٔ خرید/ارتقا/شارژ کسر می‌شود. برداشت حداقل ۱ سکه، با حداکثر یک دورهٔ ۲۴ ساعته در هر برداشت است. ارتقا یا شارژ مخزن دوره را از نو شروع می‌کند؛ UI قبل از اقدام تأیید می‌گیرد.
- کارت تصویری هدیه یک خروجی تصویری رایگان است؛ سکه یا کد قابل مصرف صادر نمی‌کند. ادعای پاداش دعوت از شمارندهٔ محلی حذف شده و تا تأیید واقعی سروری پرداختی ندارد. لینک هدیهٔ اعتباری همچنان غیرفعال است.
- ابزارهای محلی مدیریت که وعدهٔ شارژ/ریست زمان سرور می‌دادند کنار گذاشته شدند؛ شارژ خود مدیر نیز از همان واریز احرازشده استفاده می‌کند. قوانین میزها به‌جای تنظیمات محلی بدون اثر نمایش داده می‌شوند.
- مسیرهای preview قدیمی به همان صفحهٔ فعلی هدایت می‌شوند تا کیف پول موازی اجرا نشود.

## جلوگیری از دوباره‌پرداخت

کلاینت پیش از ارسال، بدنهٔ درخواست و UUID را برای همان حساب ذخیره می‌کند. قطع پاسخ یا بارگذاری دوباره همان UUID را پیگیری می‌کند. پاسخ ناقص ۲۰۰ هم قطعی حساب نمی‌شود. حساب دیگری نمی‌تواند درخواست حساب قبلی را بازپخش کند. سرور بدنهٔ عملیات را با UUID تطبیق می‌دهد؛ استفادهٔ مجدد برای مقدار/عملیات دیگر رد می‌شود.

تراکنش دیتابیس، کیف پول را قفل می‌کند، نسخهٔ دست را کنترل می‌کند و سابقه و موجودی را همزمان می‌نویسد. هر کاربر حداکثر یک دست فعال در هر بازی دارد. حرکت از نسخهٔ قدیمی دستگاه دوم رد و آخرین وضعیت دریافت می‌شود. جداول وضعیت خصوصی و درخواست‌ها با RLS و بدون دسترسی anon/authenticated نگهداری می‌شوند؛ توابع جدید فقط برای service_role قابل اجرا هستند.

## رابط پوکر

میز سبز بیضی، حاشیهٔ چوبی/طلایی، پس‌زمینهٔ تیره، آواتارهای SVG محلی، کارت‌های خوانا و دکمه‌های فولد/چک/کال/افزایش/آل‌این. حالت افقی تمام‌صفحه درخواست می‌شود و اگر چرخش سیستم ممکن نباشد خود میز با CSS به نمای افقی می‌چرخد. کلیدهای خروج و پیگیری داخل همان میز قرار دارند. رابط در اندازه‌های ۸۴۴×۳۹۰، ۳۹۰×۸۴۴، ۵۶۸×۳۲۰ و ۳۲۰×۵۶۸ بررسی شده است؛ تست دستگاه واقعی تلگرام همچنان مرحلهٔ پذیرش کاربر است.

## اعتبارسنجی و استقرار

۶۵ تست Node شامل احراز هویت، رد دسترسی غیرمدیر، قوانین بازی، حفظ ژتون در ۱۳۵ دست پوکر، حفظ ۱۵ مهرهٔ هر طرف، قطع پاسخ، بازیابی و تعویض حساب. تست HTTP با امضای تلگرام روی PostgreSQL تعبیه‌شده مسیر خرید، شروع/ادامه/پایان، خروج و تکرار درخواست را اجرا می‌کند. تست SQL مستقل، مانده و دفتر تراکنش‌ها، برداشت/واریز دوباره، نسخهٔ منقضی، خرید/برداشت ماینر و مجوزها را بررسی می‌کند. تست مرورگر با همان API و دیتابیس، موجودی خانه، کسر خرید، ادامهٔ پوکر پس از بارگذاری مجدد، کنترل‌های افقی، تخته‌نرد، رول و کیف پول را بدون خطای JavaScript گذرانده است.

استقرار به ترتیب: فقط مهاجرت جدید `20261025081053_unified_wallet_game_sessions.sql`، سپس تابع `simab-central-quests` با هر سه فایل `index.ts`، `game-api.ts` و `games.ts`، سپس رابط از شاخهٔ اصلی GitHub Pages. مهاجرت‌های قبلی را دوباره اجرا نکنید. تغییر SQL کاربر واقعی، تست واریز واقعی یا انتقال خودکار موجودی محلی لازم نیست. تمام تست‌های مالی روی محیط آزمایشی یا داخل تراکنش برگشت‌داده‌شده اجرا می‌شوند.
